# 测试交接说明 — HS-S62A-PL 读卡器板

给拿到板子做测试的同事。**不需要懂固件、不需要编译，插上线看串口就行。**

---

## 1. 这块板子能测什么

读卡。把卡片靠近读卡器，串口上会打印卡号与放行结果。

当前固件只做两件事：**读卡** + **把过程打在串口上**。没有继电器、没有联网，
所以"读卡成功"就代表这一圈全通了。

---

## 2. 接线（只有 4 根）

| 模块丝印 | 接到 ESP32-S3 | 说明 |
|---|---|---|
| G | GND | 必须接 |
| V | 3V3 | 3.3–5 V，模块板载有稳压 |
| SDA | **GPIO18**（J1 排针丝印 "18"） | 接错会读不到卡 |
| SCL | **GPIO17**（J1 排针丝印 "17"） | 接错会读不到卡 |

> ⚠️ **17 和 18 在排针上是相邻的**，别插错一格。
> 接反了不会烧，但会读不到卡 —— 固件启动时会把这种情况直接打印出来（见第 5 节）。

---

## 3. 怎么连串口

板子上有**两个 USB 口，两个都能看日志**，内容完全一样。哪个顺手用哪个：

| 口 | 系统里的设备名 | 备注 |
|---|---|---|
| 原生 USB 口 | macOS `/dev/cu.usbmodem*`，Windows `COM*` | 有些电脑需要装驱动 |
| 板载 USB-UART 口 | macOS `/dev/cu.usbserial*` / `SLAB_USBtoUART` | 走 CH340/CP2102，通常免驱 |

参数固定：**115200，8 数据位，无校验，1 停止位，无流控**。

> 交叉验证用：两个口同时插上、各开一个串口窗口，应该看到一模一样的内容。
> 如果只有一个口有输出，说明另一个口的驱动没装。

---

## 4. 正常时你应该看到什么

**插上电瞬间：**

```
=========================================================
 HS-S62A-PL 读卡器   ESP32-S3   测试固件 v1.1.0
=========================================================
 I2C 100 kHz   SDA=GPIO18   SCL=GPIO17   轮询 30 ms
 引脚定义唯一来源: src/app_config.h
 日志通道: USB + UART0(TX43/RX44)
---------------------------------------------------------
 操作方法: 把卡片靠近读卡器（有效距离 0~2cm）
           成功时打印 ">>> 读卡成功"，移开时打印 "<<< 卡片移开"
           每 10 秒打印一行 STATE 状态；无异常时不会有多余输出
=========================================================
[       1][SELF  ] I2C 引脚自检通过  SDA=GPIO18 SCL=GPIO17  无短路
[       2][BOOT  ] reset_reason=1(POWERON) 连续复位计数=1
[      45][RFID  ] 上电: 挂载成功 addr=0x28 chip=SI522A @0x28 (0x92)
[     120][BOOT  ] 读卡器就绪  addr=0x28  SI522A @0x28 (0x92)
[     121][BOOT  ] 可以开始测试：请把卡片靠近读卡器
```

三行关键信息，缺一不可：

| 行 | 含义 |
|---|---|
| `SELF  ] I2C 引脚自检通过` | 接线 OK、引脚没坏、没有焊接短路 |
| `RFID  ] 上电: 挂载成功 addr=0x28` | 找到读卡芯片了 |
| `BOOT  ] 可以开始测试` | 一切就绪 |

**刷卡（把卡贴到模块上，0~2 cm）：**

```
[    3421][CARD  ] >>> 读卡成功  UID = 27 1F BE 06    sak=0x08  [放行 ALLOW]
[    4288][CARD  ] <<< 卡片移开  UID = 27 1F BE 06    在位 867 ms  读取 29 次
```

**每 10 秒一行状态：**

```
[   10000][STATE ] 运行 10s | 进卡 1 离卡 1 拒绝 0 丢弃 0 | 链路 UP  addr=0x28 SI522A @0x28 (0x92)
```

## 5. 出问题时怎么判读

**固件会自己告诉你问题在哪，不用猜。** 对照下表：

| 串口上看到 | 说明 | 怎么处理 |
|---|---|---|
| `SELF ] !! I2C 引脚自检不合格` | 引脚对地短路 / 输出级坏 / 线断 | 检查 SDA、SCL 是否插错、焊点是否虚焊 |
| `SELF ] !! SDA 与 SCL 短路（锡桥）` | 两根线被焊在一起了 | 清理焊点 |
| `SELF ] I2C 引脚自检通过`，但 `全总线扫描无任何应答` | 总线是好的，但对面没人 | 量模块 V 与 G 之间有没有 3.3 V；确认 SDA/SCL 没接反 |
| `上电: 0x28 无应答 (endTransmission=2 NACK_ADDRESS)` | 同上（总线正常但模块不应答） | 同上 |
| `endTransmission=5 TIMEOUT` | 物理层问题 | 模块没供电 / 无上拉 / 线被拉死 |
| `链路 DOWN` 或 `LOST` | 中途掉线了 | 抖动排线看是否恢复；固件会自己重试，不用重启 |
| `WARN ] 栈水位偏低` | 固件内存配置问题，不是硬件问题 | 把这一行原文反馈给我们 |

### 关于"接反"

**SDA/SCL 接反不会烧东西**，但表现很迷惑人：总线电平、上拉、波形全都正常，
只是所有地址都不应答（错误码清一色 `NACK_ADDRESS`）。这种情况固件的诊断行会
直接把"接反"列为第一嫌疑，照提示把两根线对调即可。

---

## 6. 测试步骤建议

1. 接好 4 根线，插 USB，打开串口（115200）
2. 确认第 4 节的 3 行关键信息都出现
3. 用**手边所有能找到的卡**各刷一次，记录哪些能读、哪些不能读、读到的 UID 是什么
4. 测试读卡距离：卡从远到近，记录最早能读到的距离
5. 连续快速刷卡 20 次，看是否每次都上报、有没有重复或遗漏
6. 反复拔插排线 3~5 次，看掉线后能否自动恢复（最长 10 秒内应恢复）
7. 让它连续通电跑一段时间（建议几小时），看 `STATE` 行的"进卡/离卡"计数是否正常累加

---

## 7. 需要反馈什么

出问题时，把**从开机到出问题那段串口输出全文**贴回来即可，不用自己分析。
里面已经包含了定位所需的一切（引脚自检、扫描结果、错误码、诊断结论）。

另外请一并说明：**电压从哪来**（USB 口 / 外部电源）、**排线多长**、**哪种卡**。

## 附：如果你想自己重新烧固件

```bash
# 生产/测试固件
pio run -e rymcu-esp32-s3-devkitc-1 -t upload

# 硬件自检固件（不做业务，只把接线/引脚/芯片逐项报一遍，排查时用）
pio run -e bringup -t upload

# 看串口
pio device monitor -b 115200
```

引脚定义只在 `src/app_config.h` 一处。改接线就要同步改那里，别在别处硬编码。
